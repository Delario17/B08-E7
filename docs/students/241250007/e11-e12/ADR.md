# ADR：按提交和内容哈希传递集成产物

- 编号：B08-241250007-E11E12-01。日期：2026-11-27。作者：王祎。
- 状态：E11-B、E12 单机预演已验证。

DRAFT、BuildChecker、EChecker 与 MDFixer 需要在同一任务中交换数据。基线和修复目标使用不同 Git 提交，产物在复用或下载后仍需能定位到对应的提交与任务。

E11-B 使用随样例一起生成的固定 MD 报告，便于独立验证 B 轨道。E12 优先使用本轮 EChecker 输出的 `incremental-check.json`。阶段报告统一携带 `schema_version`、`kind`、`commit`、`job_id`、`trace_id` 与状态，产物引用附带 URI 和 SHA256。MDFixer 读取前检查目标提交和内容哈希。候选在副本上构建与验证，重检通过后产出结果。

直接传文件路径便于调试，但路径本身无法表达提交身份或检测内容变化。版本化引用增加了阶段元数据与核对成本。本次用旧报告验证 `STALE_REPORT`，并在 E12 用实际增量报告验证 URI、提交和哈希。样例中两条 MD 均消除，RD 保留。

API 使用提交任务、轮询状态、下载产物三个环节。相同幂等键和相同输入复用任务，变化的输入返回 409。服务重启时保留已完成任务，并将尚未完成的任务标为 `SERVER_RESTARTED`。单机 HTTP 预演验证了已完成任务恢复与补丁哈希，新增契约测试覆盖已完成、运行中和排队三种持久化状态。
