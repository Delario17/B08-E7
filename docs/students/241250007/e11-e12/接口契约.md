# e11e12-1 接口契约

| 方法和路径 | 请求和响应 | 已验证状态码 |
|---|---|---|
| `GET /health` | 返回服务状态与 `schema_version` | `200` |
| `POST /v1/jobs` | 请求携带 `idempotency_key` 和 `input`；返回 `job_id`、状态及请求哈希 | `202`；同键不同输入为 `409` |
| `GET /v1/jobs/{job_id}` | 返回任务状态，完成任务携带 `trace_id`，失败时携带 `error` | `200` |
| `GET /v1/jobs/{job_id}/artifacts` | 返回阶段及产物清单，含 URI、SHA256、字节数 | `200` |
| `GET /v1/jobs/{job_id}/files/{相对路径}` | 返回文件与 `X-Content-SHA256` | `200` |

`input` 包含 `mode`、`repo`、`base`、`target`、`candidate` 等字段，仓库和候选路径指向 API 主机挂载后的 `/course/data/`。`base`、`target` 使用完整 Git 提交 SHA。状态为 `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED` 或 `TIMED_OUT`。相同键和相同输入返回原 `job_id`。重启后未完成的任务转为 `FAILED`，错误码为 `SERVER_RESTARTED`。

`artifact://{job_id}/{相对路径}` 对应文件下载接口。消费者校验内容哈希、`schema_version=e11e12-1`、报告类型、状态及目标提交。全量基线报告绑定 `base`，增量、补丁和复验绑定 `target`。

单机预演使用服务器回环端口 `18081`。分机联调时在 API 主机绑定回环端口，双方交换请求 JSON 和两个提交 SHA，通过 SSH 转发访问。真实项目已经完成服务器单机 CLI 和 API 验证，分机联调结果待补。

## B08 真实项目请求

E3 Target 的 E12 请求带 `project_profile=b08-e3-target`，复用相同 API 与阶段报告。报告中的 `execution_image_id` 对应 DRAFT 实际交付给检测和复验的镜像，每次容器调用在运行日志中记录镜像 ID 和退出码。请求、原始 C0/C1、候选 Dockerfile 和输出校验以真实项目报告为准。
