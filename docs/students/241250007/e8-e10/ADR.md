# ADR：在固定版本上生成保持声明风格的 MD 修复补丁

- 作者：王祎，241250007，B08，B 轨道。
- 日期：2026-11-11。
- 关联实现：`labs/e8e10/lab.py` 的 `patch()`。
- 验证版本：`0dabf6874d06d0940a65e298d93da602aec45e7a`。

## 背景与约束

Makefile 中 main.o 漏声明 config.h，同时声明了源码未使用的 unused.h。本次任务消费带项目 commit 的报告，生成可审阅补丁，并处理 direct、macro 和 mixed 三种声明风格。补丁生成时原项目需要保持不变，过期报告应在修改前被拒绝。

## 决策

1. 报告 commit 必须等于受测项目 HEAD。使用旧报告时返回 STALE_REPORT，重新采集对应版本后再处理。
2. 本阶段仅处理 MISSING。保留 REDUNDANT 条目对应的声明，把是否删除冗余依赖留给独立策略与验证。
3. direct 在目标依赖行补齐文件；纯变量形式修改变量定义并保留目标引用；mixed 保留变量引用，在目标行补齐文件。
4. 生成 Git 统一 diff 和结构化 plan，先执行 git apply --check。原样例不直接写回；实际应用使用 apply-demo 或测试临时项目。
5. 保持编译配方字节，补丁变更集中在声明位置。通过个人测试检查 RD-only 输入与 mixed 配方保持。

## 替代方案与代价

| 方案 | 比较与选择 |
|---|---|
| 所有风格均展开成目标行 | 能统一输出形式，但会消除原变量组织方式；本次选择保留声明风格 |
| 扫描后直接改写原 Makefile | 便于立即观察修复结果，但不利于保留原输入和审阅候选；本次选择独立 Patch |
| 同时删 RD、补 MD | 会扩大补丁范围；本次只补 MD，RD 保留 |
| 先生成候选再检查版本 | 容易把旧报告位置用于新输入；本次在 patch 入口先检查 commit |

修改变量定义可能影响引用该变量的多个目标。本次 macro 样例由 main.o 引用 DEPS，参考实现没有完成共享变量的跨目标分析。扩展时可先枚举变量使用位置，再选择局部补充规则、专用变量或明确拒绝，配套多目标用例检验影响范围。

候选阶段通过不写回源文件保持原输入。E8、E9 中校验失败时源文件仍保持原字节；E10 将进一步执行沙箱构建、程序验证、重检和接受／拒绝流程。
