## 3. E8：固定报告、候选补丁和旧报告拒绝

### 输入与独立预期

样例包含 `main.c`、`helper.c`、`config.h`、`extra.h`、`unused.h` 和 Makefile。`main.c` 包含 `config.h`，但 `main.o` 只声明 `main.c unused.h`；`helper.o` 声明 `helper.c`。项目程序预期输出为 `1`。

先通过 `fixture()` 建立样例，再调用 `scan()` 保存 `fixed-md-report.json`。报告中：

- actual：main.o → config.h、main.c；helper.o → helper.c。
- declared：main.o → main.c、unused.h；helper.o → helper.c。
- findings：精确为 MISSING(main.o, config.h) 和 REDUNDANT(main.o, unused.h)。

该输入由本次本地 GCC 依赖采集生成，profile 为 `GCC_LOCAL_HEADERS_EXPLICIT_MAKE`。步骤日志记录报告 commit 与样例 HEAD 相同。

### 候选生成与原文件保护

使用 `patch(project, report)` 生成 `candidate.patch` 和 `patch-plan.json`。计划的 target 为 main.o、dependency 为 config.h、style 为 direct。补丁的实际变化为：

```diff
-main.o: main.c unused.h
+main.o: main.c unused.h config.h
```

生成补丁后调用 `git apply --check`，再检查原项目 Git 状态为空。原 Makefile 仍无 config.h，编译配方和 unused.h 均保留。日志记录 `APPLY_CHECK_PASS_SOURCE_CLEAN`。

### 旧报告拒绝

对报告副本将 commit 改为 40 个零，调用 `patch()`。实际异常为 `STALE_REPORT`，保存到 `expected-failure.json`；异常前后的 Makefile 字节一致。日志记录 `EXPECTED_REJECTION STALE_REPORT` 和 `SOURCE_BYTES_UNCHANGED`。该拒绝符合预期，因此该步骤退出 0。

主要证据位于 `work/e8-B-manual.esj5b0/`：`fixed-md-report.json`、`candidate.patch`、`patch-plan.json`、`expected-failure.json`、`project/`、`steps/` 和 `结论.txt`。

## 4. E9：三种声明风格及副本应用

对 direct、macro、mixed 分别创建独立项目并调用 `scan()`、`patch()`。每种保存输入报告、补丁和修改计划，检查补丁可应用、原文件字节不变且 Git 工作区干净。

| 风格 | 原声明 | 实际修复位置 | 结果 |
|---|---|---|---|
| direct | `main.o: main.c unused.h` | 目标依赖行增加 config.h | style=direct，STYLE_PASS |
| macro | `DEPS = main.c unused.h`，目标引用 `$(DEPS)` | DEPS 定义增加 config.h，保留目标引用 | style=macro，STYLE_PASS |
| mixed | `HEADERS = unused.h`，目标引用 `main.c $(HEADERS)` | 目标行增加 config.h，保留 HEADERS 定义和引用 | style=mixed，STYLE_PASS |

随后把 macro 项目复制到独立的 `apply-demo/`，在副本中依次执行 `git apply --check` 与 `git apply`。实际生成 `DEPS = main.c unused.h config.h`，目标仍为 `main.o: $(DEPS)`。原 macro 项目的 Makefile 字节保持不变，日志记录 `APPLY_TO_COPY_PASS`。

主要证据位于 `work/e9-B-manual.XY6fLu/`：三个原项目、三份 `*-input.json`、三份 `*.patch`、三份 `*-plan.json`、`apply-demo/`、`steps/` 和 `结论.txt`。
