## 2. E8 固定报告与候选补丁

`fixture()` 创建带内部 Git 提交的 C/Make 样例，`scan()` 通过 GCC 采集项目内头文件依赖，并与 Makefile 声明比较。最终报告的依赖关系如下。

| 目标 | 实际依赖 | 声明依赖 | 发现 |
|---|---|---|---|
| `main.o` | `config.h`、`main.c` | `main.c`、`unused.h` | 缺失 `config.h`，冗余 `unused.h` |
| `helper.o` | `helper.c` | `helper.c` | 无 |

`patch()` 先校验报告提交与样例 HEAD 一致，再处理 MISSING 条目。实际补丁只有一处声明变化，计划记录为 `target=main.o`、`dependency=config.h`、`style=direct`。

```diff
-main.o: main.c unused.h
+main.o: main.c unused.h config.h
```

这项修改补齐了 `config.h` 的构建依赖，保留了 `unused.h` 和编译配方。旧报告场景返回 `STALE_REPORT`，结果保存在 `expected-failure.json`。版本检查位于生成补丁之前，可以阻止旧报告用于不同的样例提交。

## 3. E9 三种声明风格与副本应用

| 风格 | 原声明 | 实际补丁 | 保持的结构 |
|---|---|---|---|
| direct | `main.o: main.c unused.h` | `main.o: main.c unused.h config.h` | 显式目标依赖行 |
| macro | `DEPS = main.c unused.h` | `DEPS = main.c unused.h config.h` | `main.o: $(DEPS)` |
| mixed | `main.o: main.c $(HEADERS)` | `main.o: main.c $(HEADERS) config.h` | `HEADERS` 定义与变量引用 |

三份 plan 的目标和依赖均为 `main.o` 与 `config.h`，风格分别为 direct、macro 和 mixed。macro 补丁应用到独立的 `apply-demo/`。该副本的 Makefile 中，`DEPS` 已包含 `config.h`，目标仍引用 `$(DEPS)`。

E8、E9 的验证范围是报告版本校验、候选生成、补丁应用检查及副本应用。E10 的构建、程序输出和头文件变化后的重建属于后续实验。
