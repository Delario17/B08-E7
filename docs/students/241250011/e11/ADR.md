## 背景与约束

E11-B 将 DRAFT 构建、固定 MD 报告和 MDFixer 修复连接起来。构建成功只能说明工具链和程序可运行；修复还要依据正确版本的缺失依赖报告，保持 Makefile 声明结构，并通过头文件变化和动态重检。

个人样例在 C1 增加 extra.h 包含，形成 config.h、extra.h 两个 MD。mixed 规则使用 `main.c $(HEADERS)`，其中 HEADERS 保存原有 unused.h。

## 方案与选择

| 问题 | 采用方案 | 替代方案与代价 |
|---|---|---|
| 公共实现来源 | 固定组长 PR #14 的提交，并记录个人源码版本 | 各自复制原始课程包会增加公共组件和 MakeProfile 版本不一致的可能 |
| 报告版本绑定 | 外层 commit 和内层 data.commit 都必须对应 target_commit | 只检查外层封装无法发现内层报告来自其他版本 |
| mixed 修改位置 | 在目标依赖行补齐 config.h、extra.h，保留变量引用和配方 | 展开变量或修改共享变量会扩大改动范围及受影响目标 |
| 候选接受 | 独立沙箱中全部验证通过才写回 | 直接写入源目录需要额外恢复失败修改，并保护此前已接受版本 |
| 产物关联 | 以 job_id、trace_id、commit、artifact URI 和 SHA256 关联阶段 | 只依靠文件名或目录名无法充分标识输入版本和传递内容 |

## 实际验证

direct 和 mixed 的 DRAFT 均复现 MISSING_MAKE，候选构建与程序运行成功，输出 1。两种补丁均通过五项检查，动态重检没有 MISSING，保留 unused.h 的 REDUNDANT。

mixed 实际补丁为：

```diff
-main.o: main.c $(HEADERS)
+main.o: main.c $(HEADERS) config.h extra.h
```

真实过期报告案例保持外层提交正确，修改内层提交，返回 STALE_REPORT，阶段清单只有 draft。个人测试以模拟 DRAFT 覆盖外层提交不匹配，断言修复与项目验证未调用、源文件保持不变。

完整测试共 14 项通过，其中个人新增 2 项。证据为 `work/e11-zyl-mixed-20261127-204818-6284/`、`work/e11-zyl-stale-20261127-203636/` 和 `work/e11-zyl-tests-20261127-203636.log`。

## 代价与范围

当前运行顺序先执行 DRAFT，再消费固定报告，因此过期报告也会产生构建开销；版本检查保证其在生成补丁前停止。沙箱、重复构建和动态观察增加时间及存储开销，但保留了可复查的输入、候选与验证过程。

固定 MD 输入属于受控教学样例。MDFixer 只修复 MISSING；动态结论覆盖当前配置和实际观察，不扩展为任意项目、所有配置或 E12 的真实增量联调结论。
