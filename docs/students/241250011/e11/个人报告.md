## 2. DRAFT 到 MDFixer 的集成

运行入口为：

```bash
python3 run_e11e12.py run --request <个人请求JSON> --out <新的work子目录>
```

请求包含 `mode=e11-b`、项目仓库、base/target 提交、候选路径、固定报告路径、`expected_output=1` 和 `build_timeout=7200`。实际链路为：

1. 按 base 和 target 创建独立项目快照。
2. DRAFT 构建缺陷版本，确认失败属于 MISSING_MAKE；再构建固定候选并运行程序。
3. 消费 fixed-md 输入，核对外层封装与内层报告的目标提交。
4. 根据 MISSING 条目生成候选补丁和 repair plan。
5. 在沙箱验证补丁应用、构建、功能输出、头文件变化和缺失依赖；全部通过才写回目标快照的 Makefile。
6. 调用 BuildChecker 动态重检，确认无 MISSING，并记录阶段产物及内容摘要。

成功任务包含 `draft → fixed-md → repair → recheck` 四个阶段。各阶段封装以相同的 job_id、trace_id 和 target_commit 关联；DRAFT 与 BuildChecker 另有各自的内部 trace_id。
