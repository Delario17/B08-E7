# E11–E12 接口契约（e11e12-1）

## HTTP API

| 方法与路径 | 行为 | 成功/错误状态 |
|---|---|---|
| `GET /health` | 返回服务状态和 schema 版本 | `200` |
| `POST /v1/jobs` | 使用 `idempotency_key` 提交 `input` | `202`；同键不同输入为 `409` |
| `GET /v1/jobs/{job_id}` | 查询任务状态、trace 和错误 | `200`；不存在为 `404` |
| `GET /v1/jobs/{job_id}/artifacts` | 返回阶段与产物清单 | `200` |
| `GET /v1/jobs/{job_id}/files/{relative_path}` | 下载产物并返回 `X-Content-SHA256` | `200` |

任务状态为 `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED` 或 `TIMED_OUT`。相同幂等键和相同的规范化输入必须返回原 `job_id`；相同键对应不同输入必须返回 `409 IDEMPOTENCY_CONFLICT`。服务重启后保存的幂等绑定仍然有效。

## 输入与阶段

`input` 至少包含 `mode`、`repo`、`base`、`target` 和 `candidate`；真实项目增加 `project_profile=b08-e3-target`。`base` 与 `target` 使用完整 Git SHA。E12 阶段顺序为：

1. `draft`
2. `full-check`
3. `incremental-check`
4. `repair`
5. `recheck`

五阶段必须共享相同 `job_id` 和 `trace_id`。全量报告绑定 base；增量报告、补丁和复验报告绑定 target。

## 产物约束

`artifact://{job_id}/{relative_path}` 映射到对应任务的文件下载接口。清单记录 URI、SHA256 和字节数。消费者必须校验 schema、报告类型、成功状态、提交身份和内容哈希。下载接口的 `X-Content-SHA256`、清单 SHA256 和下载后本地计算值必须相同。
