## 输入上下文与问题

向工具提供了 E8—E10 课程材料、B 组操作手册、个人身份（241250078、B08）、组仓库地址和“完成工作”的任务。问题集中在：个人应提交哪些内容、如何覆盖三阶段验收、怎样证明拒绝路径不改原文件，以及怎样从最新主分支提交。

## 模型建议

1. 先拉取并检查最新 `origin/main` 是否已经包含公共实验骨架，避免普通组员重复导入公共文件。
2. 从最新主分支建立 `student/241250078/e8-e10`，只增加个人测试与文档。
3. 在课程参考路线之外增加三个独立预期：旧报告全文件字节保护、direct recipe 字节保持、编译失败候选回滚。
4. 用固定 Docker 镜像运行手工 E8/E9/E10 流程和完整单元测试，并保存 OUT、镜像 ID、源码 SHA 与 validation JSON。

## 采纳、拒绝及理由

- 采纳：报告 commit 前置检查、sandbox 验证后写回、三种声明风格分别验证、编译失败回滚测试。这些建议与手册的质量门禁和源文件保护要求一致。
- 拒绝：没有修改公共 `lab.py`，因为现有实现已经满足实验 profile，个人贡献用测试扩展即可清楚界定；没有把 `work/` 全量加入 Git，以避免把嵌套 `.git`、二进制构建物和大量临时 sandbox 提交到仓库，完整证据改为服务器归档。
